## 2. STAR Metodu ilə Hekayələr (4 Kritik Ssenari)

### Hekayə 1: Komanda İşi və Fərqli Fikirlərin Razılaşdırılması (Teamwork)
* **Situation (Vəziyyət):** Bootcamp buraxılış layihəsində 3 nəfərlik komanda ilə bank analitikası platforması hazırlayırdıq.
* **Task (Tapşırıq):** Mən məlumat modelinin və ETL borusunun qurulmasına cavabdeh idim. Komanda yoldaşım müştəri cədvəlində bütün dəyişiklikləri köhnənin üzərinə yazmağı (SCD Type 1) təklif edirdi, çünki bunu kodlaşdırmaq daha sadə idi.
* **Action (Hərəkət):** Mən emosional mübahisə etmək əvəzinə, bank və sığorta audit tələblərini izah etdim. Bir nümunə göstərdim: əgər müştəri ötən ay Gəncə filialında kredit götürübsə və bu ay Bakıya köçübsə, Type 1 keçmiş filial hesabatını korlayacaq. Bunun qarşısını almaq üçün SCD Type 2-nin `effective_date` və `end_date` məntiqini cədvəl üzərində vizuallaşdırdım və PySpark-da birləşmə kodunu öz üzərimə götürdüm.
* **Result (Nəticə):** Komanda arqumentimi qəbul etdi. Layihəmiz tam tarixi audit dəstəyi ilə uğurla təhvil verildi və müəllimlər tərəfindən ən yetkin məlumat modeli kimi qiymətləndirildi.

---

### Hekayə 2: Gözlənilməz Texniki Nasazlıq və Bərpa (Failure & Resilience)
* **Situation (Vəziyyət):** Real-time kripto layihəsini akademik müdafiəyə hazırlayarkən, test zamanı axın qəfil dayandı və Grafana paneli boş qaldı.
* **Task (Tapşırıq):** Müdafiəyə 2 gün qalmışdı; axının niyə çökdüyünü tapmaq və sistemin təkrar sınmaması üçün dayanıqlı həll qurmaq lazım idi.
* **Action (Hərəkət):** Docker və PySpark loqlarını araşdırdım. Məlum oldu ki, ictimai CoinGecko API-si qəfil HTTP 429 (Too Many Requests) xətası verib və Producer bu xətanı tuta bilməyib çöküb. Dərhal iki qoruma qatını tətbiq etdim: 1) Python Producer-ə `urllib3 Retry` və eksponensial geri çəkilmə (`exponential backoff`) əlavə etdim; 2) PySpark Streaming-də `checkpointLocation`-u yoxladım ki, skript yenidən başlayanda heç bir Kafka ofsetini itirməsin.
* **Result (Nəticə):** Sistem hətta API müvəqqəti cavab vermədikdə belə çökməz hala gəldi, Kafka gecikmələri təhlükəsiz buferlədi və müdafiə günü canlı demo problemsiz keçdi.

---

### Hekayə 3: Tamamilə Yeni Texnologiyanı Qısa Müddətdə Öyrənmək (Fast Learning)
* **Situation (Vəziyyət):** Kafka layihəsinə başlayarkən internetdəki dərsliklərin 90%-i köhnə ZooKeeper ilə izah olunurdu, lakin sənayedə artıq KRaft rejimi standartlaşırdı.
* **Task (Tapşırıq):** Cəmi 4 gün ərzində heç bir ZooKeeper olmadan təmiz KRaft rejimində multi-broker klaster qurmalı idim.
* **Action (Hərəkət):** Köhnə video dərslikləri kənara qoyub, birbaşa Apache Kafka-nın rəsmi sənədləşməsini (KIP-500 və KRaft Quickstart) oxudum. `kafka-storage.sh` ilə vahid cluster-id formatlama əmrlərini və Controller rollarını araşdırdım. Lokal Docker Compose faylı yazıb 3 brokerli KRaft klasterini addım-addım qaldırdım və brokerlərdən birini söndürərək qəza bərpasını test etdim.
* **Result (Nəticə):** 3 gün ərzində KRaft rejimini tam işlək vəziyyətə gətirdim. Bu təcrübə mənə rəsmi sənədləşmə ilə işləmək və ən yeni texnoloji standartları sürətlə mənimsəmək inamı qazandırdı.

---

### Hekayə 4: Təzyiq Altında Məlumat Qüsurunun Həlli (Problem Solving)
* **Situation (Vəziyyət):** Bank ETL borusunu test edərkən 500,000 sətirlik tranzaksiya faylında 150 sətirdə `customer_id` xarici açarı müştəri cədvəlində tapılmadı (orphan FK).
* **Task (Tapşırıq):** Bütün ETL-i dayandırmaq olmazdı (çünki qalan 99.9% tranzaksiya düzgün idi), lakin bu xətalı sətirləri fakt cədvəlinə buraxmaq da hesabatı pozardı.
* **Action (Hərəkət):** Mən 'Quarantine Pattern' (Karantin Modeli) arxitekturasını qurdum. Düzgün sətirləri normal Gold cədvəlinə yönləndirdim, xətalı 150 sətri isə ayrıca `quarantine_transactions` qovluğuna yazıb yanına `reason = 'ORPHAN_CUSTOMER_ID'` və daxilolma tarixini vurdum.
* **Result (Nəticə):** Hesabat vaxtında hazır oldu və eyni zamanda xətalı qeydlər itirilmədən audit üçün təcrid edildi. Bu, mənə istehsalatda elastik mühəndislik kompromislərini öyrətdi.

## 3. Müsahibəçiyə Veriləcək 10 Ağıllı Sual (Smart Questions to Ask)

Müsahibənin sonunda *"Bizə hər hansı sualınız var?"* deyildikdə mütləq 2-3 dənə dərin və maraqlı sual ver:

1. **İnfrastruktur haqqında:**
   > *"Atəşgah Sığortada hazırda SQL Server əsasən hansı versiyadadır və gələcək PostgreSQL infrastrukturunu on-premise serverlərdə, yoxsa bulud mühitində (məsələn, AWS RDS/Aurora) qurmağı planlaşdırırsınız?"*
2. **Miqrasiya strategiyası haqqında:**
   > *"SQL Server-dən PostgreSQL-ə miqrasiyada əsas yanaşma kimi nəzərdə tutulur: müəyyən pəncərədə böyük keçid (Big-Bang), yoxsa CDC ilə tədricən modulların köçürülməsi?"*
3. **Mövcud kod bazası haqqında:**
   > *"Mövcud SQL Server mühitində biznes məntiqi daha çox Stored Procedure və Function-larda cəmlənib, yoxsa tətbiq və ya ETL səviyyəsində idarə olunur?"*
4. **Lakehouse və Analitika haqqında:**
   > *"Sığorta zərərləri (claims) və polislər üçün nəzərdə tutulan Lakehouse arxitekturasında hansı cədvəl formatına (Delta Lake, yoxsa Apache Iceberg) daha çox üstünlük verirsiniz?"*
5. **Məlumat həcmi və tezliyi:**
   > *"Şirkət daxilində gündəlik emal olunan tranzaksiya və hadisə həcmi təxminən nə qədərdir və real-time axınlara (məsələn, Kafka) ehtiyac hansı modullarda var?"*
6. **Data Komandası strukturu:**
   > *"Hazırda Data komandasında neçə mühəndis və analitik çalışır və komandada kod icmalı (code review) və arxitektura qərarları necə müzakirə olunur?"*
7. **İlkin gözləntilər:**
   > *"Bu vəzifəyə seçiləcək Junior Data Mühəndisindən ilk 3 ay ərzində hansı konkret nəticələri və töhfələri gözləyirsiniz?"*
8. **Data Keyfiyyəti və Monitorinq:**
   > *"Hazırda boru kəmərlərinin monitorinqi və xəta bildirişləri üçün hansı alətlərdən (Airflow callbacks, Telegram/Slack alertləri, Grafana) istifadə edirsiniz?"*
9. **Domen və Biznes Öyrənməsi:**
   > *"Komandaya yeni qoşulan mühəndisin sığorta biznes qaydalarını və anderraytinq məntiqini daha tez mənimsəməsi üçün hər hansı daxili sənədləşmə və ya mentorluq prosesi varmı?"*
10. **Şirkətin gələcək baxışı:**
    > *"Bu miqrasiya və Lakehouse layihəsi tamamlandıqdan sonra Atəşgah Sığortada məlumat platformasının növbəti böyük inkişaf mərhələsi nə olacaq (məsələn, Real-time Fraud Detection və ya Data Science modelləri)?"*
